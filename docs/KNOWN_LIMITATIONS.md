# Known limitations in 0.1.0-preview.1

Kerneon is created and published by **Ryan Horth**.

These are explicit product boundaries, not hidden or simulated features.

- Frame proof uses the optional official Intel PresentMon 2.5.1 provider. Without it, Kerneon continues to monitor the PC but labels FPS, 1%/0.1% low, p99/worst frame time, hitch rate, display delay, dropped presents, limiter signal, and Frame HUD measurements unavailable. PresentMon GPU execution metrics can be less accurate under Hardware-Accelerated GPU Scheduling; Kerneon exposes provider warnings and refuses causal proof after lost ETW events. A 30-second 0.1% low can represent only a handful of frames and is labelled as short-window evidence; release-grade comparisons need longer controlled captures. The non-injected HUD is designed for the Windows compositor/borderless presentation path; a true legacy exclusive-fullscreen path can cover it, which Kerneon will not bypass through injection.
- NVIDIA temperature, utilization, power limits/draw, clocks, P-state, and limiter reasons are read natively through the driver-supplied NVML runtime. Tuning Lab audits the current and legacy public core-offset, VRAM-offset and power-limit surfaces and enables only controls supported by that device/driver. The AMD ADLX adapter reads live telemetry, manual GPU/VRAM clock ranges where available, per-silicon automatic clock engines, and Reset to Factory. Intel IGCL, fan, voltage, CPU-package, and motherboard sensor normalization remain incomplete. Kerneon does not install a kernel driver to fabricate a universal sensor layer.
- GPU engine and memory values depend on Windows PDH counters and the installed display driver. Unsupported systems show an unavailable state.
- Process detail includes per-process history, parent/child context, path tools, and safe Below normal/Normal/Above normal scheduling preferences. Per-process GPU/network attribution, command line, signature/publisher, connections, suspension, and termination are not yet exposed. Surge can repair a severe game-process affinity restriction transactionally, but the general process page does not expose arbitrary affinity editing.
- Surge is an allowlisted session controller, not an unrestricted “PC cleaner.” Guarded mode repairs only detected execution QoS, scheduling, reduced memory priority, and severe affinity restrictions. Aggressive mode can create a disposable Windows CPU policy, isolate up to two measured same-session user contenders, and use documented NVIDIA per-game maximum-performance or refresh-aware frame-limit values. The separate Tuning Lab can discover direct NVML power/clock headroom only after hardware-risk consent and elevation. Experimental treatments are withdrawn if comparable proof shows no material benefit.
- Tuning Lab is deliberately GPU/VRAM-only. Direct NVIDIA controls depend on the current driver's public NVML support; the current RTX 2080 SUPER driver exposes bounded core, VRAM and power writes through NVML's current clock-offset API. Radeon controls depend on ADLX per-card capability. Processor and system-memory overclocking are outside Kerneon's scope. Kerneon refuses undocumented SMU/MSR/register drivers that would turn a privileged paid product into a vulnerable ring-0 utility.
- The Tuning Lab preview uses an explicitly requested elevated application session. Remote Link remains available in that session for paired monitoring, which means the LAN listener currently shares the elevated process even though its session, origin, local-grant and fixed-allowlist checks still apply. Before commercial release, hardware mutation should be isolated in an authenticated, signed, on-demand broker and adversarially tested. A recovery snapshot improves rollback but cannot recover from every driver, OS, power or hardware failure.
- Surge needs a locked game process but does not need a known title: an unknown executable receives the universal engine. Optional verified title adapters add game-owned evidence; they are not the compatibility boundary. Documented NVIDIA application power/cap values have exact rollback; AMD/Intel per-game profile writes and Windows Graphics preference remediation remain diagnostic/guided until equivalent adapters are available.
- Remote Link is LAN-only HTTP bound to one private address. It is not an internet relay or safe to expose through router port forwarding. Pairing and WebRTC signaling remain HTTP, so a hostile active LAN observer is outside the current threat model even though Kerneon Session data channels use WebRTC DTLS. Pairing creates an eight-hour device session; general control additionally requires a visible local 15-minute or Until-revoked grant. The allowlist covers Surge, Game Focus, incident capture, verified installed-game launch, and current-process game locking—never shell commands or arbitrary paths.
- Kerneon Session is a responsive remote support preview, not a gaming-streaming codec. It sends native Windows GDI captures as up-to-1280-pixel JPEG frames at about 8 FPS. It has no audio, clipboard, file transfer, multi-touch gesture synthesis, adaptive video codec, NAT relay, or internet traversal. Windows secure-desktop/UAC surfaces and DRM/protected pixels are intentionally unavailable. Current mobile/desktop WebRTC browsers are the target; a broader physical browser/device matrix is still required before public release.
- Compact mode is a small always-on-top window, not an injected game overlay; it has no anti-cheat certification or click-through overlay controls.
- History and captured incidents are memory-only. Persistent/downsampled multi-day storage is not implemented.
- Optional AI requires a user-supplied OpenAI API key, internet access, and separate API billing. It receives an anonymized telemetry digest and cannot execute remediation actions.
- Network rates cover one selected adapter. Per-process connection ownership is unavailable; virtual/filter interfaces are excluded from automatic selection to avoid double counting.
- Protected process fields and mutations may be refused by Windows. Kerneon does not elevate itself to bypass those protections.
- Recognised anti-cheat processes/services force external-only Surge and suppress the Kerneon HUD, driver-profile writes and all game-process mutations while the default guard is enabled. A user can explicitly disable that extra guard, accepting compatibility/account risk; doing so does not add injection, hooks, game-memory rights, anti-cheat manipulation or a kernel component. No application can guarantee compatibility with every current or future third-party anti-cheat policy.
- Windows PDH correlates DPC/interrupt, scheduler, page-in and storage pressure with long-frame windows, but it does not identify the responsible kernel driver by itself. Driver attribution requires a bounded ETW trace and should remain diagnostic until the trace consumer, overhead budget and retention policy are release-tested.
- The portable executable is not Authenticode-signed because no publisher certificate was provided. Windows reputation prompts may therefore appear on another PC.
